# FROZEN CONTRACT — dmj.one Trusted Documents · PHASE 2: The Three Modes

Status: **FROZEN** (2026-06-08). Builds on the Phase-1 foundation (`2026-06-08-trusted-documents-foundation.md`, committed): `kind` discriminator, `LetterContent`/`UploadAttestation`/`SignaturePlacement`, `computeLetterCanonicalPayload`/`computeUploadCanonicalPayload`/`computeCanonicalPayloadForRecord`, decoupled `signer.sign(unsignedPdf, buildCanonicalPayload)`, `verifyMldsaForRecord`, `DOCUMENT_ID_PREFIX={letter:'LTR',upload:'DOC'}`, `issueLetterSchema`, `signUploadSchema`. The cert canonical payload stays FROZEN (golden test). Everything here is normative; values (APIs, routes, coords, pipeline order) are exact.

The three modes:
- **Mode 1 — Certificate (any type):** free-text type on the existing ornamental template + the rich body editor (already shipped).
- **Mode 2 — Letterhead:** dmj.one letterhead, large multi-page rich body for long letters, issued as a verified Trusted Document.
- **Mode 3 — Upload & attest:** upload a PDF → stamp a visible validation ID (QR) → optional handwritten-signature stamp (placed + resized) → PAdES + ML-DSA + log → download; verifiable by document number.

It ships in two dependency-ordered build phases: **2A** (render layer + mode-1 schema) then **2B** (issuer routes + verify page + admin console, parallel, against 2A's rebuilt dist).

## §F. Cross-stream API contracts (pin these; all streams code to them)

### F.1 Render package new exports (`packages/render/src/index.ts`)
```ts
// Mode 2 — letterhead letter → self-contained HTML (fonts/images inlined), flowing multi-page.
export function buildLetterHtml(input: { content: LetterContent; qrDataUri: string }): string;

// Mode 3 — stamp an uploaded PDF (pure pdf-lib; no Chromium). Returns NEW bytes.
export interface StampInput {
  pdfBytes: Uint8Array;
  documentId: string;            // the visible validation id; also the QR target tail
  verifyUrl: string;             // full https URL the QR encodes (verify.../c/<documentId>)
  issueDateIso: string;          // YYYY-MM-DD, shown in the stamp
  signature?: { pngBytes: Uint8Array; placement: SignaturePlacement }; // optional handwritten stamp
}
export function stampAttestation(input: StampInput): Promise<Uint8Array>;

// Inspect an uploaded PDF without modifying it (for the placement UI). pdf-lib only.
export interface PdfInspection { pageCount: number; pages: Array<{ widthPt: number; heightPt: number }>; }
export function inspectPdf(pdfBytes: Uint8Array): Promise<PdfInspection>;
```
- `buildLetterHtml` reuses the brand palette + the four serif `@font-face` (base64, via `getFontFaceCss()` / `getBrandImages()` like `template.ts`/`section63-template.ts`), the rich body via `compileParagraph` (per-paragraph `<p class="pa-*">`), and is a FLOWING document (`@page{size:A4;margin:…}`, `break-inside:avoid` on the signature block) like the §63 template — NOT the single-page absolutely-framed cert. Every interpolated field HTML-escaped.
- `stampAttestation` (pdf-lib, `useObjectStreams:false` on save so the result carries a CLASSIC xref table the PAdES signer needs): on EVERY page draw a compact validation stamp in the bottom margin — a small QR (≈16mm, encoding `verifyUrl`) + the line `dmj.one Trusted Document · <documentId> · verify at verify.dmj.one`, in a faint band that sits in the margin and never overlaps page content (measure page box; place within the bottom ~14mm). If `signature` present, draw the PNG on `placement.page` at `xPct·W, (top) yPct·H, width wPct·W`, height = width·(imgH/imgW). QR PNG generated by the render package's existing QR utility (reuse whatever `renderer`/`template` already use to make the cert QR data-URI; expose the raw PNG bytes for pdf-lib embedding).
- `inspectPdf`: load via pdf-lib, return page count + each page's `{widthPt,heightPt}` (PDF points). Throw a typed error on a non-PDF / encrypted / corrupt file.

### F.2 Issuer routes (all behind `requireAdmin`, mounted in existing route files / new ones under `services/issuer/src/routes/`)
- **Mode 1:** existing `POST /api/credentials` — extended to accept a custom `type` (see §A).
- **Mode 2:** `POST /api/letters` — body `issueLetterSchema`; runs the letter issuance pipeline (§B.3); returns `{ documentId }`, 201. `POST /api/letters/preview` — body = `issueLetterSchema` minus `password`; side-effect-free; returns `application/pdf` (the exact letter render with placeholder id `DMJ-LTR-00000000-00`). (Mirror the cert preview route exactly.)
- **Mode 3:**
  - `POST /api/uploads/inspect` — body `{ pdfBase64: string }`; returns `{ pageCount, pages:[{widthPt,heightPt}], originalSha256 }`; side-effect-free (no allocation, no store).
  - `POST /api/uploads/preview` — body `{ pdfBase64, placeHandwrittenSignature, signaturePlacement? }`; stamps with the PLACEHOLDER id `DMJ-DOC-00000000-00` (+ optional signature) via `stampAttestation`; returns `application/pdf`; side-effect-free (NO sign/allocate/store/log/audit).
  - `POST /api/uploads` — multipart OR `{ pdfBase64, ...signUploadSchema fields }`; the full attest pipeline (§C.3); returns the SIGNED PDF bytes (`application/pdf`, `Content-Disposition: attachment; filename="<documentId>.pdf"`) plus the `documentId` in a response header `X-Document-Id`.

## §A. Mode 1 — Certificate (any type)

Today `issueCredentialSchema.type` is an enum of 5; ID code comes from `CREDENTIAL_TYPE_CODES[type]`. Relax to allow a custom type while keeping the 5 presets:
- `issueCredentialSchema.type`: accept the 5 known codes OR a custom string (`z.string().trim().min(2).max(40)` matching `/^[a-z][a-z0-9 -]*$/i`). Keep `CredentialType` as `string` at the content level (the 5 presets stay as suggested values; do NOT break existing records).
- ID code for a custom type: derive a 2–4 letter uppercase code — `CRT` if no clean derivation, else the first up-to-4 `[A-Z]` of the uppercased type (fallback `CRT`). Keep the 5 presets' existing codes exactly (so existing IDs/sequences are unaffected).
- Display label: presets keep their labels; a custom type's label is the type string Title-Cased. Update `TYPE_LABEL` lookups (verify page, §63) to fall back to Title-Case for unknown types (this overlaps the §D kind-aware work — coordinate: the fallback is a `?? titleCase(type)`).
- The ornamental certificate template is UNCHANGED; only the kicker/title/type vary.

## §C. Mode 3 — Upload & attest (the new subsystem)

### C.1 Inputs / limits
PDF only. Decode `pdfBase64` (or multipart file) → `Uint8Array`; reject > 10 MiB, non-PDF (no `%PDF-` header), or `inspectPdf` failure with a uniform 400. `originalFilename` sanitized to a basename (strip path, `[^A-Za-z0-9._ -]` → `_`, ≤200 chars).

### C.2 Placement model
`SignaturePlacement` fractions are relative to the page box, origin TOP-LEFT (UI space). `stampAttestation` converts to pdf-lib's BOTTOM-LEFT origin: `pdfY = H - (yPct·H) - sigHeight`. The handwritten signature PNG is the existing dmj.one signature asset (reuse the brand signature image bytes the cert sig block uses); transparent PNG preferred.

### C.3 Attest pipeline (`POST /api/uploads`, side-effecting)
Order (mirrors cert issuance; the documentId must exist BEFORE stamping because the QR encodes it):
1. validate (`signUploadSchema` + the PDF bytes) → `originalSha256 = sha256Hex(pdfBytes)`, `pageCount` via `inspectPdf`.
2. allocate `documentId = DMJ-DOC-<date>-NN`.
3. `stamped = await stampAttestation({ pdfBytes, documentId, verifyUrl: `${VERIFY_PUBLIC_URL}/c/${documentId}`, issueDateIso, signature: place ? { pngBytes: signatureAsset, placement } : undefined })`.
4. `sig = await signer.sign(stamped, (h)=>computeUploadCanonicalPayload(attestation, h))` where `attestation: UploadAttestation = { documentId, issueDate, originalFilename, originalSha256, pageCount, signaturePlacement: place?placement:undefined, signatory: DEFAULT_SIGNATORY }`.
5. §63 metadata over `sig.pdfSha256`; append log; hash `password`; `credentialRepo.create({ id:documentId, kind:'upload', content:attestation, status:'valid', ...sig, ...log, passwordHash, section63 })`; `blobStore.put(documentId,'certificate',sig.signedPdf)` + §63; anchor; audit.
6. respond `application/pdf` (the signed bytes) + `X-Document-Id`.
   The signed PDF is ALSO retrievable later via the gated download (password) like certs, and re-downloadable by the admin from the dashboard.

### C.4 Verify (Stream VERIFY) — upload records resolve at `/c/<documentId>`; the verify page shows the upload variant (§D). The signed PDF's `pdfSha256` is recorded, so the existing upload-a-file verify path also matches.

## §D. Verify-page generalization (`services/verify`, Stream VERIFY)
The verdict logic (`verifyMldsaForRecord` + log + not-revoked) is already kind-agnostic. Make the 4 cert-only content reads kind-aware via `documentKind(record)`:
- `publicFieldsOf`: branch — certificate (existing fields), letter (subject/recipient summary, issue date), upload (documentId, originalFilename, originalSha256, pageCount, issue date).
- `renderCredentialPage`: branch the "credential details" + hero copy by kind. Certificate UNCHANGED. Letter: "Letter · <subject or recipient>" hero, details (date, issuer, id, status). Upload: "Attested document · <filename>" hero, details (document number, filename, SHA-256, pages, date, status); honest copy ("dmj.one attests it signed this document; the document's content is the uploader's"). All fields HTML-escaped; no body re-render (uploads have no body; letters show metadata only, not the full letter — the letter PDF is the gated download).
- `buildSection63Html`: already generic over `CredentialRecord`; just make its `content` reads kind-aware (record identity row: certificate → title/recipient; letter → subject/recipient; upload → filename + original SHA-256).
- `TYPE_LABEL`: fall back to Title-Case for unknown/custom (mode 1).

All CSP-safe: class-based, no inline styles, no execCommand-style attrs; placement drag via pointer events updating a `pa-*`-style class-free transform is NOT allowed (inline style blocked) — instead position the box with left/top/width as CSS custom properties set via `el.style.setProperty` (CSSOM is allowed by CSP; only HTML `style=""` attributes are blocked) OR via a small set of class steps; PREFER CSSOM `element.style.left=…` (permitted) for smooth drag.
